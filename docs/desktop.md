# luneAgent 桌面端

桌面端在 Windows 10/11 上运行，使用 Wails v3、Svelte 5 和 TypeScript。它与现有终端程序并行安装：`bin/lune.exe` 仍启动 TUI/CLI，`bin/lune-desktop.exe` 启动桌面窗口。TUI 与 Desktop 可以同时打开同一项目；两者的会话、队列和检查点独立保存。

## 构建和运行

安装 Go 1.27.1、Node.js 22.12+、npm 和仓库固定的 Wails CLI：

```powershell
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.34
./scripts/build.ps1
./scripts/build-desktop.ps1
```

桌面二进制输出到 `bin/lune-desktop.exe`。运行桌面程序需要 WebView2 Runtime；如果缺少运行时，启动错误窗口会提供安装说明。

### Windows Beta 安装包

安装 NSIS 3.x 并确保 `makensis` 在 `PATH` 中，然后运行：

```powershell
./scripts/package-desktop.ps1
```

脚本生成两个 Windows x64 安装包：

- `bin/luneAgent-0.1.0-windows-amd64-user-setup.exe`：当前用户安装，无需管理员权限。
- `bin/luneAgent-0.1.0-windows-amd64-machine-setup.exe`：所有用户安装，需要管理员权限。

如果目标电脑缺少 WebView2 Runtime，安装器会运行 Microsoft Evergreen Bootstrapper，因此需要联网。运行时安装失败会中止桌面端安装并显示错误提示。

卸载默认保留 `%APPDATA%\luneAgent\settings.db` 中的模型设置和加密 API 密钥。卸载器提供可选复选框，勾选后清除当前运行卸载器账户的设置；该选项不会删除工作区文件或其他 Windows 用户的数据。卸载前先退出 luneAgent。

Beta 安装包尚未签名，Windows 可能显示 SmartScreen 提示。安装器和桌面端只包含 GUI 程序；现有 `bin/lune.exe` TUI/CLI 仍单独构建。

## 首次设置

在模型设置中添加提供方、模型 ID 和默认模型。API 密钥保存在 `%APPDATA%\luneAgent\settings.db`，并由当前 Windows 用户的 DPAPI 加密。前端只接收密钥是否已保存的标记，留空可保留已保存的密钥。

Desktop 的提供方、模型档案、默认模型、主题和最近工作区保存在当前用户的 `settings.db`。TUI/CLI 继续使用自己的工作区 `config.json`，不读取 Desktop 数据库。Desktop 的项目运行设置（上下文窗口、自动压缩、输出预留、图片限制和 MCP 服务）按规范化项目路径保存在 `settings.db` 中；同一项目的所有会话共用这些设置。

Desktop 完全忽略项目中的 `config.json`，不会导入、迁移或改写它。需要配置 Desktop 时，在工作区侧栏打开“项目设置”；需要配置 TUI/CLI 时，编辑工作区的 `config.json`。两套配置各自独立。

Desktop 会话数据保存在用户配置目录下 `luneAgent/desktop/<project-hash>`。TUI/CLI 继续使用项目内 `.luneagent`。升级后已有 `.luneagent` 数据保持原样，Desktop 从独立会话列表开始，不自动复制旧会话。旧版 Desktop 留在用户缓存目录 `luneAgent/worktrees` 下的 Git 工作树不会自动删除，也不会再被读取或管理。

Desktop 不再区分 Local 与 Worktree，也不依赖 Git：每个新会话都直接操作所选工作区目录。需要隔离并行修改时，请使用外部 Git 和 IDE；Desktop 只负责会话、Agent 执行和代码修改。

## 界面布局

桌面端采用两栏布局：左侧 300px 侧栏只保留品牌、工作区、会话与待处理入口；右侧是对话区，顶部 56px 状态栏显示当前会话、运行状态、后台进程、主题切换和工作区菜单。对话正文与输入框限制在 820px 列宽内，保持长对话的可读性；窗口窄于 960px 时侧栏变为遮罩抽屉。支持浅色、深色和二次元壁纸三种外观，`Ctrl/Cmd+K` 聚焦会话搜索。

## 视觉系统

界面采用“Ink & Aurora”视觉语言：浅色主题是暖纸白与墨色文字，深色主题是石墨底与冷色环境光，二次元主题是壁纸上的半透明玻璃。品牌标、欢迎页轨道插画和空会话光晕都使用内联 SVG/CSS，不依赖网络图片；设置页主题选择使用迷你界面预览卡片。装饰光晕和纸张纹理只作为背景层，不改变对话列宽、侧栏尺寸或交互行为。

动效只用于新消息、空状态、弹窗和焦点反馈，并遵守 `prefers-reduced-motion`。浅色/深色/二次元三套主题共用同一组间距、圆角和层级 token。

## 启动与窗口

Desktop 会记住上次打开的工作区、活动会话和窗口尺寸（DIP）。下次启动会自动恢复它们，窗口仍居中显示；不保存窗口位置，避免多显示器变化后窗口落在屏幕外。主动关闭工作区会清除工作区和会话恢复点，下次启动回到欢迎页。

如果上次工作区已被移动、删除或被另一个 Desktop 实例占用，启动会回退到欢迎页并清除失效的恢复点；如果上次会话已删除，则选择该工作区的首个可用会话，没有会话时创建新会话。窗口尺寸限制在 `980×640` 到 `4096×2160` DIP；缺失或非法值使用 `1440×920` 默认值。

## 运行中发送与编辑

任务运行时仍可编辑输入框并发送后续消息。新消息会显示在对话中，按顺序排队，当前任务结束后执行；审批、提问、恢复卡片或 Plan 确认待处理时，需先处理当前请求。

已进入会话历史的用户消息可以编辑。编辑会从该消息开始回退并重新运行，移除后续对话记录；任务运行期间提交历史消息编辑时，会先中断当前任务并取消后续排队消息，再回退重跑。已经执行的文件操作不会自动撤销。

排队中的消息可以单独撤回或编辑。撤回只取消选中的待执行消息，不会中断当前任务或改变其余消息顺序；编辑排队消息会替换该位置，并取消后续排队消息。

## 会话权限与 Plan 模式

每个 Desktop 会话独立选择 `read-only`、`workspace`、`ask` 或 `full-access` 权限。开启 Plan 模式时，该会话的有效权限固定为 `read-only`，关闭后恢复其原有权限；其他会话不受影响。运行、排队或有待处理任务时不能修改该会话的控制设置。

`read-only` 默认允许工作区读取，可审批工作区外目录的只读访问；`ask` 默认只允许工作区读取，其他操作均需审批；`workspace` 默认允许工作区读写，工作区外文件访问、命令和网络需审批；`full-access` 允许所有已注册工具，极度危险命令始终被阻止。工作区外文件授权按 session 保存，只作用于内置文件工具；新 session 和分叉 session 不继承，删除 session 后清除。

新会话和重新打开工作区后的会话默认使用 `workspace`、关闭 Plan 模式。这些开关不写入数据库；修改模型或项目设置造成的内部 Core 重建会保留当前开关。已接受的任务将执行权限保存在自己的队列与检查点中，恢复任务沿用该权限。

选择实施方案后，源会话退出 Plan 模式；新上下文继承源会话的基础权限。基础权限为只读时，实施按钮沿用 Core 的单轮 `workspace` 实施授权，不改变会话基础权限。实施请求失败时保留原来的 Plan 开关。

切换会话不会中断后台任务。连续点击会话时按顺序完成切换请求，并展示最后选择的会话；切换期间暂停发送和控制设置。会话相关操作都显式携带目标会话 ID，中断还校验执行 ID，迟到的响应不会修改其他会话的界面。

关闭工作区并确认中断时，会取消运行中的任务和排队消息，再关闭共享 Core 与执行记录数据库；暂停中的任务保留为可恢复状态。关闭期间不会再启动新的会话操作。

## 待处理与后台进程

待处理视图汇总当前工作区所有会话需要用户处理的请求。选择会话后，桌面端切换到对应对话完成授权、回答、恢复或 MCP 交互；侧栏只显示请求类型和工具/服务器名，不保存请求正文，也不发送系统通知。

后台进程降级为顶栏状态入口：有进程时显示“N 个进程”或“N 运行中”，点击打开浮层，按会话列出命令并读取选中进程的实时输出，可停止单个进程。没有进程时不显示入口；运行时不可访问的会话会注明原因且不提供操作。进程状态和日志沿用 Core 的会话存储，不增加 Desktop 数据表。

每轮执行会将工具返回的文件改动按路径汇总，并保留各步骤返回的差异片段。工具详情和改动摘要会随桌面执行记录保存；桌面端不提供代码编辑器、集成终端、文件浏览器或 Git 变更视图，代码编辑继续交给外部 IDE。

## 会话与 MCP 管理

侧栏可搜索会话标题和全部可读取的用户/助手对话正文，结果可直接定位到命中的消息；工具执行详情和图片不参与搜索。搜索覆盖当前工作区所有会话，结果按最近更新排序，最多显示 100 条、每个会话最多 3 条。侧栏也可重命名和删除会话，并显示运行状态。不同会话可以并行运行，切换会话不会中断后台任务。删除当前会话时先切换到其他会话；如果没有其他会话，会先创建一个新会话。删除会同时清除 Desktop 执行记录与会话数据，不影响工作区文件。

项目设置面板可编辑上下文、自动压缩、输出预留、图片限制和 MCP 服务（本地进程参数、远程 HTTP 地址及环境变量），也可查看连接状态、启用或停用服务，并为远程 HTTP 服务启动授权。环境变量值使用当前 Windows 用户的 DPAPI 加密保存在数据库中，前端只会收到变量名称和是否已配置的标记。更改项目运行设置会在所有会话空闲后重建该工作区的 Core，并恢复当前选中的会话。

## 前端预览与截图

`cmd/desktop/frontend` 包含确定性的浏览器预览页面，不连接真实 Core：

```powershell

npm ci
npm run dev
```


### 状态回归测试

`tests/session-controls.spec.ts` 在 Desktop API 边界注入确定性响应，覆盖独立权限、Plan 恢复、设置失败、连续切换以及迟到的提交和中断响应；它使用生产状态控制器，不依赖预览分支。Go 测试同时覆盖多会话共享 Core、配置重建和生命周期清理。运行 `go test -race ./internal/desktop ./internal/settings` 可检查并发访问（Windows 需要启用 CGO 并安装 C 编译器）。
